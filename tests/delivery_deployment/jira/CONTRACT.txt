Scope

Expose the already implemented ASPM_JIRA_API_ORIGINS runtime setting through
delivery.jiraAPIOrigins in the Helm chart. Default exactly [] in values.yaml.
Delivery remains opt-in. A nonempty selection does not enable the worker.
An enabled worker receives a single literal environment STRING containing
the JSON array in the caller's order. Do not join entries with commas,
double-encode JSON, invent a vendor origin or use a Secret/ambient fallback.
Empty or omitted selection adds no environment variable and preserves the
existing Slack-only default. Global values are not an origin-selection source.

Helm null removes a merged key, so an explicit null is treated as omission,
not serialized to the runtime as JSON null. The runtime still rejects a
literal JSON-null ASPM_JIRA_API_ORIGINS value. These are distinct boundaries.

Only the delivery main container receives the setting. Core, ingestion,
reports, collection, assessment and all init containers receive no Jira
origin environment. Existing DB/key selectors, Slack gateway, independent
role activation and storage separation remain unchanged. Enabling all six
roles in the new fixture must not change this isolation.

Chart validation

The effective non-null value must be an array of at most 16 strings.
Reject wrong types, null/non-string entries, empty/whitespace entries,
exact duplicate strings and obvious non-origin shapes: non-HTTPS scheme,
credentials, trailing slash/path, query, fragment, wildcard or control text.
Fail rendering with the delivery.jiraAPIOrigins path, also while delivery is
disabled. Do not echo a credential-bearing invalid value in the error.

Full canonical DNS/IP syntax, effective-port alias uniqueness and all actual
transport admission remain governed by the published runtime validator.
Do not duplicate its entire host parser in Helm or claim rendering alone
proves native network policy. Positive values include canonical DNS origins,
an explicit port and bracketed IPv6, and the full 16-entry bound. Their JSON
strings must reach the rendered worker unchanged.

Operator documentation

Update the existing deployment/runtime documentation with an explicit Helm
selection and its empty default. Explain that network admission is additional
to workspace connection approval and does not verify Jira permissions.
For the unchanged manual Quadlet, show the same JSON setting in the existing
protected /etc/aspm/delivery.env. Podman 4.9 env-file parsing retains the
right-hand-side value, so do not put shell-style quotes around the whole JSON
array. JSON quotes around the individual strings are required.
Example file line:
ASPM_JIRA_API_ORIGINS=["https://jira-gateway.example.invalid"]

The existing delivery Quadlet, installer copying/start behavior, Secret
provisioning and worker activation remain unchanged. This slice does not add
automatic installation, trust-store modification, CA/key generation, cluster
deployment or systemd activation. Existing literal environment-file routing
and previous native generator evidence are not a new environment-file run.
