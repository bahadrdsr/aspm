========================================================================

Scope
-----
This NEW tests/collection_runtime package authors four real runtime narratives.
It does not modify the accepted source backend/A2 tests/bindings, old runtime,
UI/deployment, module dependencies or oracle history. The role reuses
app.OpenCollectionWorker/ProcessNext, not a second outbox or collector.
No command/runtime behavior is claimed from helper compilation.

-----------------------------------

  ASPM_COLLECTION_S3_ENDPOINT
  ASPM_COLLECTION_S3_BUCKET
  ASPM_COLLECTION_S3_PREFIX
  ASPM_COLLECTION_S3_REGION
  ASPM_COLLECTION_S3_ACCESS_KEY

For core, ALL absent means CollectionStorage:nil and preserves unrelated old

MUST forward this actual selected pointer into app.Open so real source enqueue
and authorized evidence reads work through the core SERVICE, not just through
an app-only constructor. The role's existing raw Evidence configuration remains
separate and unchanged.

Collection environment and role isolation
-----------------------------------------
Collection requires all six of its own storage fields, DB configuration and
canonical standard-base64 ASPM_INTEGRATION_ENCRYPTION_KEY for exactly 32 bytes.
The variable names are the same as core, but the separately launched process
receives its explicit publisher identity. Missing own fields fail; raw S3/AWS/
bootstrap or ambient provider credentials are not fallback authority.

The role owns one CollectionWorker DB pool; MaxConnections=1 is valid.
CollectionLeaseDuration defaults to exactly 15s; optional
ASPM_COLLECTION_LEASE_DURATION must be 250ms..1 minute without silent clamping.
ASPM_GITHUB_ENDPOINT defaults to https://api.github.com and is trusted process
configuration only: validated HTTPS base, no credential/query/fragment/unsafe
path/control values. API or source JSON cannot choose it.

ASPM_COLLECTION_CA_FILE is optional, explicit, bounded PEM for a trusted source
gateway. Normal certificate/hostname verification remains enabled. Only a
synthetic public fixture certificate is written by tests, never a private key
or system trust-store change.

Environment builds a bounded explicit client: normal TLS (including valid
effective TLS ranges), Proxy:nil, no cookie jar, no redirect following, and
configured-origin-bound transport. Programmatic tests supply their exact owned
certificate-validating TLS client. The implementation may reuse/factor the
accepted delivery transport builder rather than creating insecure alternatives.

Default CollectionLimits are the accepted native bounds:
  Requests:32, Pages:8, PageSize:50, Bytes:8 MiB.
Programmatic selected bounds are forwarded; this increment adds no unrelated
generic configuration framework or new environment knob matrix.

Collection role returns zero raw Evidence, empty BootstrapToken/Assets/
ReadinessKey and false PrepareReadiness. It may ignore unrelated malformed raw
readiness settings but must validate its OWN inputs. No core/auth handler is
exposed. Existing core/reports/ingestion/delivery environment behavior remains.

Pure validation decision
-----------------------
The accepted app.CollectionWorker constructor validates before opening its own
pool, but its validation is currently constructor-local. service.Run must
validate the full role before EnsureSchema or listener/provider/storage I/O.
The parent may narrowly factor/export that pure validation and reuse accepted
transport validation without changing backend behavior. No test shim or
constructor call that opens a DB is accepted as a fake no-I/O validator.

Health, readiness and scheduling
--------------------------------
GET /healthz reports service:collection and status:alive.
GET /readyz reports service:collection, status:ready, database:reachable and
storage:configured-not-probed after a real DB readiness check. That label is
configuration truth, NOT proof of S3 write permission or provider authority.
No HeadBucket/ListBucket startup probe is permitted.
GET /api/session, /api/v1/session and / return 404 for the collection role.

The runtime loops the accepted ProcessNext. Only an idle false,nil result may
use a short context-aware wait. Native failure/blocked records are terminal
under the accepted backend policy; the runtime must not requeue/retry them.
Cancellation stops TLS/S3 reads/writes, listener and resources within bounds.
It does not claim to undo an already accepted remote operation.

Actual core/service/command evidence
-----------------------------------
The core test starts real service.Run("core") from service.Environment("core")
with a separately selected RO collection capability. A real protected TLS
forwarder passes unchanged HTTP to the owned core listener. Actual core APIs
create workspace, users, source connection and queued collection.

The independent collection SERVICE reads the real owned TLS GitHub repository/
alert responses, writes real selected S3 evidence, commits the stable asset,
and exposes exact evidence through the core service's RO key. It does not
normalize findings. Repeated collections must retain the one linked asset.

Held native TLS and held S3 publication are each canceled by the actual service
context. The failed collection cannot commit an accepted asset/snapshot. A
fresh ACTUAL cmd/collection-worker process must preserve prior failed/blocked
state, then process a separately authorized new valid collection.

The runner builds the real command binary from cmd/collection-worker; no
substitute test binary or handler is allowed. Private config travels in its
process environment, not command arguments. Only the correct publisher storage
identity and DB/key/gateway/CA settings are passed; raw storage, S3/AWS chains,
bootstrap, core assets and unrelated credentials are stripped.

Windows graceful cancellation is exercised through real service.Run context
while dependencies honor it. Later command cleanup kills only its exact owned
PID after terminal/new-job assertions. That bounded cleanup is not a claim
of OS-signal graceful command shutdown.
