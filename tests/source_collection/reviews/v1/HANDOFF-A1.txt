Exact authorized change
-----------------------
All existing method/path/query/capability checks remain byte-identical and occur
before body access. Only after the request passes them and an actual PUT hold
gate exists, the fixture:
  - rejects a declared body above the existing native maximum 32 MiB bound;
  - reads at most that bound plus one byte and explicitly fails read/overflow;
  - preserves the exact bytes in an io.NopCloser(bytes.NewReader(body));
  - signals arrived and waits for the same context cancellation or release.

The 32 MiB ceiling is the existing native maximum, not an increased worker
request bound. The current 32 KiB source fixture limits and all HTTP/request/
test timeouts are unchanged. No header, Host, path, query, ContentLength,
signature, credential or request permission is assigned/rewritten by the
insertion. Ungated PUTs and other methods retain their original behavior.
There is no invalid-body success default or fabricated S3 response.

The change is an exact 18-line insertion inside the gate. The rest of the old
fixture bytes, including checks and ReverseProxy forwarding, are identical.
AMENDMENT-A1.json records the exact insertion and full old/new hashes.
