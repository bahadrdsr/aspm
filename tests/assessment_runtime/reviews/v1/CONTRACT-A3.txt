Proposed timeout meaning, not implementation architecture
---------------------------------------------------------
A valid selected ASPM_ASSESSMENT_REQUEST_TIMEOUT is the assessment request's
end-to-end budget, including waiting for nonstreaming response headers.
The actual Environment-generated client must retain the parsed budget.
The assessment's shared transport must not independently cut a 20-second
request off at the old 10-second default while its approved operation is live.
A zero ResponseHeaderTimeout with the bounded total request deadline, or a
header timeout consistent with the selected budget, can both satisfy this
behavior. No particular field-setting or new internal API is prescribed.
Do not globally raise delivery/collection timeouts or change their defaults.

Go's net/http documentation distinguishes the complete Client.Timeout budget
from the transport's header-only wait after the request body is sent. This
is supporting public terminology only. Actual owned execution, not a field
inspection or documentation assumption, determines this regression's result.
