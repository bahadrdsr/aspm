M01 FRONTEND TEST-AUTHOR HANDOFF
==============================

Scope
-----
This is a browser/test/build scaffold, not the production UI or completed M01.
M00 contracts, Go schemas and other projects are untouched. No authentication
backend, ingestion implementation, live connector or hosted AI is required here.
M00 review still gates M01 completion. The normal UI must show genuine API
failures until Go implements the declared endpoints; it must not load this test
corpus as a production fallback.

Run from C:\bahadr\serious\aspm\web:
  npm.cmd ci
  npm.cmd run test:install-browser
  npm.cmd run typecheck
  npm.cmd run test:harness
  npm.cmd test
  npm.cmd run build

npm.cmd avoids an npm.ps1 invocation-wrapper problem in this Windows environment.
For registry access in this environment, set process-local
  $env:NODE_USE_SYSTEM_CA = '1'
before invoking npm.cmd. The Playwright child runner enables the same setting
and rejects NODE_TLS_REJECT_UNAUTHORIZED=0. Project npm configuration keeps
strict-ssl=true. Do not disable certificate verification or change machine-wide
TLS settings. Query explicit stable versions, never blindly the default tag.
The usual npm commands work on other development hosts. Direct dependencies are
exactly pinned; package-lock.json locks transitive dependencies. No special CI
provider is involved. dependency-metadata.json records registry metadata and
selection limitations. React canary versions were deliberately not selected.
Direct official-endpoint re-verification remains unavailable in this session:
the canonical registry still failed TLS negotiation with system CAs enabled
(an earlier official version-page request returned HTTP 403). All nine existing
stable pins were rechecked through the configured npm-public mirror using system
CAs and strict TLS verification. No versions or default tags were substituted.
The project .npmrc keeps npm cache files local and permits the configured registry
to replace historical mirror URLs in the lockfile. For a canonical-registry build:
  npm.cmd ci --registry=https://registry.npmjs.org
An offline clean install using that registry selection has also been validated
against the downloaded integrity-locked package cache; the environment's public
package mirror is not a required CI service or source-build dependency.
Playwright uses only a project-local headless Chromium cache. No browser or
application process is detached; Playwright owns and stops its loopback Vite
server. ASPM_WEB_TEST_PORT may select an unused port (default 48217).
.cache, .artifacts, node_modules and build outputs are ignored.

Why browser tests, not mocked components
---------------------------------------
Two harness tests prove React JSX/event handling in a real browser and a static
Vite build without relying on production App code. A third exercises the
fail-closed source/license approval predicate with in-memory synthetic records;
those records never authorize an actual upstream revision. The tiny counter
under tests/harness is clearly test-only and is never the missing application.
The acceptance suite mocks ONLY the HTTP boundary using Playwright routing.
React, navigation, controls, focus, themes, Motion and CSS are not substituted.
This avoids calling a jsdom preference stub proof of composed reduced motion.
No Vitest/testing-library dependency is needed for this bounded browser suite.

Expected coder-owned entrypoints
--------------------------------
  index.html
  src/main.tsx
  src/App.tsx
  src/components/provenance.json

The first three form the real production React/Vite application. Tests visit its
actual root URL, not a wrapper that implements its behavior. Until it exists,
the browser gates fail with "M01 production UI is intentionally missing".
The foundation gate checks independent source approval first and reports the
unresolved licensing prerequisite before reading any component source.
Assets and Reports may be honest M01 placeholders with their proper headings;
these tests do not require M04 inventory/auth or M05 ingestion.

Compact read-only HTTP contract
------------------------------
All responses are JSON with apiVersion="aspm/v1alpha1".

GET /api/v1/work?q=<optional filter text>
  {apiVersion,dataOrigin:"synthetic"|"live",items:WorkItem[],total,
   nextCursor:string|null}
  WorkItem:
    {id,title,assetName,severity:"critical"|"high"|"medium"|"low"|"info",
     ownerName:string|null,workflowState:"open"|"in-progress"|"resolved",
     sourceScanAt:RFC3339|null,collectedAt:RFC3339,importedAt:RFC3339}
  q searches title, assetName or ownerName. M01 may filter its small response
  locally; future Go query/pagination handling must preserve the same semantics.
  Source scan time is not a collection/import freshness substitute.

GET /api/v1/findings/<id>
  {apiVersion,dataOrigin,finding:{...WorkItem,scopeLabel,description,
    evidence:{text,sourceLabel,verificationState:"not-run"|"blocked"|"verified"},
    remediation}}
  These tests use deterministic, synthetic evidence only and never claim
  independently verified findings. No artifact URL or storage credentials are
  needed in the M01 detail prototype.

GET /api/v1/integrations/catalog
  {apiVersion,dataOrigin,items:[{id,name,kind:"native",capabilities:[],
    supportMaturity,connectionState,readyToConnect,
    liveVerification:{state,reason}}]}
  Support and connection state are separate. The fixture has all eight families
  planned/unconfigured/not-run, with readyToConnect=false. There are no passwords,
  provider tokens, credential values, secret recovery fields or credential-read
  endpoints in this DTO. Do not return raw backend configuration to populate UI.

403/404/503:
  {apiVersion,error:{code:"forbidden"|"not-found"|"unavailable",
    message,requestId,retryable:boolean}}

api-contract.ts gives precise test-only TypeScript DTOs; fixtures.ts contains
only synthetic data. The HTTP fixture rejects undeclared endpoints, writes,
provider/bearer credentials and external requests. Browser storage may hold
non-secret preferences, never long-lived credentials. Backend authorization,
redaction and isolation need their own later Go contract/integration tests;
M01 mocks are not evidence that an unimplemented backend enforces these rules.

  LICENSE.md Git blob: 0ca4a48bd712fd8db31fff20c8b241c5cf41e4db
The coordinator independently read the full standard MIT text and confirmed

That is recorded as license-only evidence, NOT approval of copied components or

tests/approved-component-sources.json separates licenseReviewedCandidates from

An approvedSources entry has:
  {provider:"shadcn"|"animate-ui",repository,commit,path,sourceSHA256,
   license:{expression,path,gitBlob,snapshotPath,sha256,additionalTerms:[]},
   approval:{status:"approved",authority:"coordinator"|"independent-reviewer",
     foss:true,perFileLicenseReviewed:true,dependencyClosureReviewed:true,reviewRef}}

Approval must bind the exact immutable commit, source path/hash, full applicable
license text/hash and copied/registry dependency closure. Animate UI requires
the exact candidate commit/license-blob pair plus separate per-file and dependency
approval. A root license review cannot fill those approval fields automatically.
The helper also rejects Commons Clause text even if a record calls it
MIT and gives that text a matching hash. Source and license snapshots are read
only after a matching independent approval exists. No source is fetched by tests.
These checks enforce the recorded policy; they are not an automated legal audit.

Only after approval may the coder adopt the corresponding reviewed source.
Runtime dependencies, tokens, styles, notices and the compatible primitive
choice belong to that implementation phase. The provenance gate expects:

src/components/provenance.json:
  {schemaVersion:1,primitiveFamily:"radix"|"base-ui",components:[
    {id,provider:"shadcn"|"animate-ui",localPath,localSHA256,
     upstream:{repository,commit,path,snapshotPath,sha256,license},
     adaptation:"verbatim"|"reviewed-patch",patchRef?,reviewRef}
  ]}

Repository IDs are shadcn-ui/ui and imskyleen/animate-ui. Commits are full
40-character hashes, not mutable branch labels. The claimed license must match
the independent approval, not a blanket assumption about today's upstream.
Snapshots, reviews and optional
patches are nonempty web-relative files; upstream snapshots can be .txt files
under tests/upstream to avoid compiling duplicate raw component sources.
localPath is under src/components. SHA-256 values describe UTF-8 content with
CRLF normalized to LF. License Git blob IDs additionally bind the EXACT raw bytes
using Git's blob header and byte length. Semantic whitespace comparison is not
substituted for byte identity. tests/upstream snapshots are marked -text in the
web .gitattributes so Git does not rewrite their line endings. Verbatim copies

The final foundation gate still requires approved source from both providers

The independent reviewer must verify upstream snapshots against pinned commits,

M08 V25 bounded bulk accepted-risk browser increment (October 8, 2026)
---------------------------------------------------------------------
The existing selected-findings toolbar adds one action named Accept risk. It
does not add bulk suppression, false-positive, disposition clearing, proof, AI,
workflow inference or automatic expiry behavior. Existing assign, unassign and
workflow actions keep their exact request bodies and never send risk fields.

The accepted-risk form has one optional expiry control and one required
rationale control. Blank expiry means an explicit acceptedRiskExpiresAt:null.
A supplied expiry is sent as one RFC3339 timestamp strictly after the fixture
server time. The form explains, before submission, that the service creates one
finding-scoped immutable approval per finding and that accepting risk does not
verify safety.

The request contains exactly findingIds, decisionRevisions, disposition,
acceptedRiskExpiresAt and rationale. findingIds are the selected lowercase
32-hex IDs. decisionRevisions has exactly one current positive revision for
each selected ID and no other key. disposition is accepted-risk. The request
does not contain ownerId, workflowState, dispositionScope, approval IDs, actor,
workspace, verification, proof or source fields.

The current revision and accepted-risk display state come from canonical Work
items. The client does not invent revisions, approval IDs or successful state.
It sends no mutation for an empty selection, a blank/NUL/over-8192-byte
rationale, an invalid/nonfuture expiry or any invalid selected item. More than
100 selected findings keeps Apply disabled and explains the limit.

A successful canonical response must contain exactly one item per requested ID
in ascending ID order, total equal to that count and nextCursor:null. Only then
does Work update the selected rows, accepted-risk labels and loaded accepted-risk
count. It clears the completed selection and risk draft while preserving the
current filter, sort, page, scroll and a safe focus position in Work.

A 400, 403, 409, 503, malformed 200 response or transport failure retains the
selection, expiry and rationale draft and keeps the last confirmed rows/count.
Stale 403 and 409 responses are not retried automatically. A protected 401
clears all workspace state and returns to Sign in.

Viewer Work keeps read-only selection but has no accepted-risk mutation control.
Displayed role metadata never overrides a current server 403. Workspace change,
session loss and logout abort a held bulk request, clear its draft and selection
from the old scope, and discard a late acknowledgement. The V25 control remains
usable at 390px in both reduced and ordinary motion without horizontal overflow
or motion-dependent completion.

Strict parsing rejects missing, extra, duplicate or out-of-order response IDs,
wrong totals, a nonnull cursor, malformed decision/disposition metadata and
undeclared fields required for the committed Work update. A rejected response
never fabricates an approval, accepted-risk label, count or success message.
No rationale, expiry, revision map, finding state or approval-like value is
stored in browser storage or written to console output.

M10 V26 bounded report export browser increment (October 9, 2026)
----------------------------------------------------------------
Reports adds one closed-by-default region named Report exports. Opening it
performs one explicit first-page GET with limit=100. It does not load exports,
page snapshot history or poll while closed. Any current member can open the
region, read history, select an export and explicitly refresh history or
detail. Load more exports uses only the returned native cursor and never
automatically drains later pages.

Admins and analysts see one Create report export form. The snapshot selector
contains only succeeded snapshots already returned by Saved snapshots. It does
not fetch or auto-drain additional snapshot pages. The format selector contains
JSON and CSV. One explicit submit sends exactly snapshotId, format and a fresh
nonblank NUL-free idempotencyKey of at most 256 UTF-8 bytes. The key is generated
in memory and is not displayed as authority, persisted in browser storage or
reused for a genuinely new confirmed intent. Viewers have no create form or
enabled create action but retain all read and download behavior.

A 202 receipt is shown as queued, never generated or complete. Detail has one
explicit Refresh export control. Queued, processing, failed and succeeded are
rendered only from strict server receipts. Queued and processing have no
download. Failed shows the exact bounded diagnostic and no download. Succeeded
shows digest, size and safe filename and has one Download action. There is no
status polling or automatic retry.

Download fetches the same-origin content endpoint in memory, validates exact
Content-Type, attachment filename, X-ASPM-Content-Digest,
X-ASPM-Content-Length, byte length and SHA-256, then creates one Blob/object URL
download and revokes that URL. JSON LF and CSV CRLF bytes remain exact. No
artifact body, digest, filename, snapshot ID, export ID or object URL is written
to localStorage, sessionStorage, IndexedDB, cookies, the page URL or console.

A lost, aborted or otherwise ambiguous POST acknowledgement retains one
unresolved snapshot/format/key intent. It does not paint optimistic success,
generate another key, issue an automatic replay or enable unrelated new export
creation. An explicit Refresh exports may reconcile a matching history receipt;
an explicitly offered pending replay must send the exact original body. Only
after authorized reconciliation may a genuinely new submit use a fresh key.

A transient history failure retains the last authorized rows and exact native
cursor. A transient detail failure retains only currently authorized metadata.
A detail 403 or 404 withholds prior metadata and latches that boundary through
later loading and transient failures until an authorized success. Workspace
change, session replacement, logout and protected 401 abort old-scope history,
detail, creation and content requests, clear rows and unresolved intent, and
discard late responses. Displayed role metadata never overrides a current
server denial.

Strict parsing rejects wrong API version or data origin; unknown or missing
envelope/export keys; wrong workspace, snapshot, requester or export identity;
invalid format, state, time, failure, digest, size or filename; inconsistent
state metadata; duplicate, descending or cross-workspace pages; invalid totals
or cursors; content headers that disagree with the selected receipt; unsafe
Content-Disposition; missing or malformed digest/length; and body bytes whose
length or SHA-256 differs. A malformed replacement never becomes a row,
terminal state or download.

At 390px with reduced motion, opening the section, creating an export, native
Load more, manual Refresh export and Download remain keyboard reachable without
page-level horizontal overflow. Request completion preserves deliberately moved
focus. Existing Reports and Work context remains intact.
