Surface and scope
Reuse the existing "Filter findings" text input as an editable draft. Typing,
clearing that local filter, sorting and display-page navigation remain local
and issue no HTTP. Add "Search all findings", with Enter in the input doing
the same explicit submission. This searches the selected workspace only,
not every workspace, scanner, source account or a consistent global snapshot.
No second search panel, extra navigation, saved views, sort API or filter DSL.

Trim a submitted draft. Nonempty text is NUL-free and at most 512 UTF-8 bytes,
not 512 characters. Invalid input has an accessible alert, aria-invalid on
the input, and no HTTP or successful empty-result transition. Do not truncate
or silently replace it. A valid 512-byte trimmed query is permitted.

A status named "Workspace search" identifies the confirmed query separately
from the editable input. For bare results it says "No server search". For
search results it identifies the confirmed query, the workspace scope and
that these are server results. It must not label old rows with a pending,
failed or merely edited query. Loading/failure messages describe old results
honestly. "Clear search" and an empty submitted draft explicitly request the
bare native first page, clear the draft, and restore focus to the input.

Retain the existing honest "Finding pagination" status: loaded row count,
last returned service total and whether native continuation remains. Counts
may differ and pages are not an atomic snapshot. Finding/Severity sorts and
the unsaved draft still apply only to loaded rows. No automatic draining,
per-keystroke fetching, debounce timer, polling or promise of full scanning.

Exact existing HTTP
Initial/default load and a confirmed clear: GET /api/v1/work, no query/body.
Submitted nonempty query and its refresh: GET /api/v1/work?q=<trimmed-query>,
with q ONLY, no limit or cursor on the first page.
Manual search continuation and its retry: GET /api/v1/work with exactly q,
limit=100 and the service's native 32-lowercase-hex cursor. Order is irrelevant.
No duplicates, offsets, generated predicates, role/actor/revision authority,
server-sort or other parameters. Refresh uses the CONFIRMED query, not draft.
Retry search uses the exact failed first-page query. Retry more findings uses
the exact failed query AND native cursor even if the draft has since changed.
The existing backend queryText/workFilter is read-only, not changed or
qualified by these synthetic browser tests. No backend/API/schema work.

Replacement, concurrency and decisions
Explicitly submitting a different query or clearing can supersede a pending
query, refresh or continuation. No duplicate automatic operation is allowed.
Until success, keep only still-authorized last confirmed rows and their old
query label; local draft filtering can hide them. A successful DIFFERENT
query atomically replaces rows and native frontier, resets display page to
one, and clears query-specific selected IDs, including hidden selections.
It must not overwrite a newer unsaved draft. Same-query refresh retains
the published usable local context while resetting its native frontier.
Old responses cannot mix rows/frontiers/labels across queries.

Canonical finding PATCH ACKs still protect row reads started before the ACK,
including older search reads. Do not inject an ACK's otherwise-unloaded ID
into another query's results. Keep the published local-match/focus behavior.
An owner update can invalidate an older query's observed membership: preserve
the canonical row fields and honestly say search membership needs refresh,
rather than inventing a new server membership or relabeling old API counts.
The next authorized query read can establish its own actual membership.
All original source, evidence, scan, provenance and verification fields stay
unchanged; only explicitly declared existing human PATCH intents may mutate.

Authority, memory and transport
Work 403/404 clears protected Work rows and selected IDs. Failed/pending new
searches, old continuations and independent detail ACKs cannot recover them.
Only a subsequently authorized Work 200 can recover that Work view. A detail
can keep its separate authority without authorizing denied Work results.
Global 401, workspace/session change and logout discard private Work/finding
context. Released old requests must not restore it or cross scope/epoch.
Keep draft/confirmed search in memory across Settings/Work navigation only;
workspace/session changes clear both. No private storage, readable cookie,
URL persistence of search text, external traffic, scanner/AI/provider calls.

Transport observations are evidence, not invented browser guarantees.
Register requests before awaiting allHeaders. Record actual response,
requestfinished and requestfailed events. StrictMode entries admit one or two
declared scoped calls, at least one observed completed 200, and no fallthrough
default response for a denied entry. A global 401 is proved by its real
response event before failure plus real App Sign in; a later authority-driven
body abort is permitted. Superseded reads may actually abort or complete,
but neither outcome may change the newer UI. Reload explicitly if a new
document is intended; hash-only navigation is not a reload.
