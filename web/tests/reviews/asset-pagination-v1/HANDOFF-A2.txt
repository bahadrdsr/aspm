Exact distinction from AP4
-------------------------
AP4 holds a read begun before the mutation; the save then triggers another,
unheld GET. That later read settles quickly and applies the pending ACK.
A2 instead validates and holds the mutation response first, queues a held
cursor="" read, releases the validated ACK, and waits for the NEW save-triggered
GET. It asserts request ordering and that the new GET has not settled.

Before releasing that new GET, canonical inventory data and selector options
must already incorporate the complete 200/201 mutation DTO. A confirmed ACK
does not need a later successful/failed list read to become visible.
Unacknowledged form data must still remain non-optimistic.
