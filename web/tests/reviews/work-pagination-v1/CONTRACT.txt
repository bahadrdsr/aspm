Scope and surface
-----------------
This closes inaccessible native Work continuation only. Server search/sort,
saved views, global-result sorting and broader M05 completion remain OPEN.
Keep the five navigation links, initial bare Work request, existing Work
context, 50-row display pages, Previous/Next and human finding actions.
No timers, automatic draining/polling, new navigation or new backend/API.

Inside "Finding work queue", add one button "Load more findings" when an
authorized confirmed nextCursor remains. Busy state disables duplicate load
activation, while confirmed rows and other usable local controls stay present.
Continuation errors expose an alert and "Retry more findings"; retry preserves
the exact failed native cursor and limit. Refresh remains the existing Refresh.
Exhaustion can remove or natively disable Load more findings.

An accessible status named "Finding pagination" describes all confirmed LOADED
rows and the LAST RETURNED server total, independent of the local filter.
Explain whether more results remain and that separate pages/counts are not a
single atomic snapshot. Existing 50-row page text can describe filtered loaded
matches. Clearly state that BOTH filtering and Finding/Severity sorting apply
only to loaded findings, even after the last known cursor is exhausted.

Exact HTTP and authority
-----------------------
Initial load, scope/session entry and manual first-page Refresh:
  GET /api/v1/work
  No query and no body.
An explicitly consumed continuation:
  GET /api/v1/work?limit=100&cursor=<32-lowercase-hex-native-ID>
  No body. Query order is irrelevant. No duplicate query keys.
No q, offset, page number, sort, saved-view, role, actor, credential or other
authority is added. Filter/sort changes issue ZERO HTTP.
Keep the real shared typed parser/errors and bounded query encoder; reuse or
extract pure helpers rather than inventing a second parser/framework.

The original first-page parser may preserve an UNUSED legacy synthetic cursor.
Do not reject its otherwise valid first page merely because an old fixture
never intends to consume that cursor. Validate before consumption: a malformed
cursor must produce an explicit error without HTTP or losing confirmed rows.
Once continuation is requested, malformed metadata or a nonadvancing/repeated
nextCursor is an explicit failed page, not success/exhaustion/automatic retry.
Keep the last confirmed frontier available for exact manual retry.

Successful native pages merge by ID without duplicate visible rows. Native
server order is retained before optional local loaded-row sorting. Failed
continuations commit no rows/cursor/total. An authorized empty tail with null
cursor can end continuation; an empty/error/denied response without that
authorized null does not. A later total may differ from loaded count.

Refresh and reconciliation decisions
------------------------------------
A successful explicit bare refresh starts a new canonical first-page set and
resets continuation to THAT response's cursor. Unlike the prior Assets cut,
do not preserve an old Work continuation frontier after this replacement.
Keep active filter/sort/selection and usable display-page/focus context.
Never automatically fetch remaining pages to reconstruct the old set.

A canonical finding PATCH ACK is visible immediately in a loaded row. A read
started before ACK cannot overwrite it. Starting another page after that ACK
must not withdraw its protection from older already-loaded page snapshots.
Track source/request order as appropriate; no server revision/header is
invented. New reads can reconcile their own current canonical rows.
Opening/closing a finding and owner changes moving it out of a local filter
must preserve coherent context/focus. A valid detail ACK for an UNLOADED ID
must not manufacture a Work row or increase loaded count.
Only explicit existing human actions mutate findings; Bulk actions remain
unavailable and all original source/evidence/verification fields stay intact.

Errors, denial and epochs
------------------------
503, a failed network read and invalid continuation metadata retain permitted
confirmed rows and the failed cursor for explicit retry, with an honest alert.
Authoritative Work 403/404 clears ALL protected Work rows and selected IDs.
Those rows/selections stay withheld during pending/failed 503 reads until an
authorized Work 200. Do not show "No findings" as a denial/failed-read success.
An authorized detail response/PATCH ACK is NOT a new Work authorization.
Do not infer global cross-route permission: a still-authorized open detail
may retain its own context/actions while Work alone is denied.

Workspace switch, global 401 and logout abort old reads and discard old Work/
finding contexts. Released old-scope pages cannot append or cross workspaces.
Keep cookie/workspace authority, server role checks and existing session flow.
A stale cached analyst role cannot turn a server-rejected PATCH into success.
Viewer Work reads remain useful; Work continuation itself is GET-only.
