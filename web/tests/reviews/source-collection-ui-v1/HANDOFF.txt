Authoritative API facts for the coder
------------------------------------
Source profile is only github-cloud-app, selecting one bounded owner/repo.
POST /api/v1/sources has profile/name/repository/token/enabled only.
PATCH selects only intentional name/repository/token/enabled fields. Blank
replacement input is omission, not an empty token PATCH. Revision comes from
the server. Stored credentials never imply Connected or live verification.
There is no browser operator-key/endpoint/header/approval/requester editor,
OAuth installation or native bearer refresh.

POST /api/v1/sources/{id}/collections accepts only idempotencyKey.
202 means queued, not collected/scanned/verified. Identical replay is 200 with
the same complete immutable binding/result. Lost ACK cannot silently create a
new job. Only an explicit user confirmation may collect.

Collection/history/record paths and JSON names are exact in CONTRACT.txt.
In particular:
  - rawURL uses that exact capitalization.
  - Evidence path is /sources/collections/{collectionID}/records/{recordID}/evidence.
  - There is no separate GET /records/{recordID} metadata endpoint.
  - Evidence is raw application/octet-stream, not a JSON response envelope.
  - Failed early settlement has gaps:[] and recordCount:0.
  - Partial can retain valid repository/alert records with alerts:rate_limited.
  - retryAfterSeconds is data only, never a timer that collects or polls.
  - GitHub nativeRunId is empty; sourceScanAt is null. sourceUpdatedAt is
    native update provenance, never a source scan time.
  - kind:finding is a raw alert record, not an application normalized finding.
  - complete means exhausted selected feeds, not scanner/verification success.

All three lists use bare default 100 and native 1..500 limit / ID cursor.
Fixtures are bounded to 102 sources, 101 collection-history rows and 102 raw
records, with ID ordering separate from ordinal. No auto-drain/search/offset.
