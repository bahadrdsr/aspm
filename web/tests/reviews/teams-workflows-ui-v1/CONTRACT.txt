403/404 withholds only that resource's cached fields and actions, including after

session based on the actual HTTP status, not an error string or aborted request.

Configuration and secret handling
---------------------------------
Admin only: Add Teams connection/Edit Teams connection form; Name, password
"Workflow URL", Enabled, and checkbox "I acknowledge Workflow ownership".
The acknowledgement starts UNCHECKED on create. Explain standard-channel/Anyone
signed Workflow scope, owner/co-owner continuity and that team ownership does
not supply Workflow ownership. Ownership, permissions and channel delivery are
NOT verified. Fixed standard channel, no channel-type picker or extra identities.
Save Teams connection is explicit. Cancel and dialog close discard the draft.
Only current authorized metadata is read on edit. There is no credential readback,
delete API, test/probe button, runtime origin policy or vendor authentication UI.
Disabling is an enabled:false edit. Blank Workflow URL preserves by OMISSION.
Name/enabled/workflowUrl/teams PATCH fields are sparse, never token/channel/jira,
profile, identity, routing, override or client-revision authority. An unchanged
edit sends nothing. A changed teams declaration is a whole two-key object, never
a partial merge. In this published profile every VALID declaration is already
{channelType:"standard",ownershipAcknowledged:true}; therefore rotation does NOT
invent a declaration change or resend teams, even when its derived origin changes.
POST includes the complete two-key declaration. This is a backend-derived oracle
clarification, not permission to change an old test or native contract.

Name uses the published nonblank <=256 UTF-8-byte rule. URL uses the published
<=16384 UTF-8 bytes and <=4096 decoded-path bytes, not JS character counts.
Require canonical HTTPS origin: lowercase host, no trailing dot/userinfo/fragment/
opaque form, no explicit :443, canonical nondefault port. Callback path must be
nonempty and not "/", with no controls, repeated slashes, dot segments, backslash,
decoded %, ?, #, encoded slash/backslash or double-encoded routing separators.
Query must parse successfully, with exactly one decoded nonempty sig and no
whitespace in sig or decoded controls in any query key/value. Reject malformed
escapes. Safe encoded path letters and repeated NON-sig parameters are allowed.
Send the ENTIRE original URL unchanged, preserving query order/case/encoding and
safe path escapes. Parsing for validation is not permission to serialize it back.
Do not truncate/coerce rejected input or echo it in accessible error text.

Workflow URL and ALL its path/query values are secrets. Hold only in input/ref
and the explicit same-origin configuration request; clear on success, cancel,
close, scope change, logout or 401. Password DOM input value while editing is the
intentional exception, not an API. No readback, label, preview, navigable link,
storage, URL/hash/search, console or clipboard export. Safe derived origin may
appear as plain text only after canonical acknowledgement, never a callback link.
Correctable error retains a password draft; denial disables configuration.
Native/server echoes, including standalone sig/path/query values, are never shown
verbatim. A generic mutation failure is safer than exposing a bearer-equivalent URL.

Exact REST and parsing
----------------------
All application requests use native versioned routes, session cookie, selected
workspace header, normal same-origin JSON and Origin on writes. No extra
Authorization/token/bootstrap/idempotency/revision headers.
GET /api/v1/integrations/connections
GET /api/v1/findings/{findingId}/deliveries
  EXACTLY one profile=teams-workflows-channel, limit=100, optional native cursor.
  Native items,total,nextCursor, ascending exclusive IDs; do not filter a mixed
  response client-side or invent counts/cursors. Reject the whole malformed page.
GET /api/v1/integrations/connections/{id}
GET /api/v1/integrations/deliveries/{id}
  No query. Individual native ID, workspace and expected profile must match.
POST /api/v1/integrations/connections, 201:
  {profile:"teams-workflows-channel",name,enabled,workflowUrl,
   teams:{channelType:"standard",ownershipAcknowledged:true}}
PATCH /api/v1/integrations/connections/{id}, 200:
  Only changed name/enabled/workflowUrl/whole teams declaration. Blank URL omitted.
  URL+enabled rotation is one write, revision +1; same URL can be a backend no-op.
Connection has ten common keys plus teams and permissionState:"not-verified".
channel:"" is a schema sentinel, not a configuration input. teams is exactly
{workflowOrigin,channelType:"standard",ownershipAcknowledged:true}.
Analyst/viewer can read safe origin/declaration/credentialConfigured/revision,
never configure. Wrong profile/scope/ID/revision/status, unexpected secret fields,
malformed metadata or mismatched acknowledgements fail explicitly with no invented
successful row. CredentialConfigured is envelope presence, not native permission.

History semantics
------------------
Exactly 15 common delivery keys + destination + outboundAttemptedAt:null|timestamp.
No jira/createAttemptedAt/payload.fields. States ONLY queued,dispatching,accepted,
blocked,failed,rate-limited,uncertain. Native202 is accepted with receipt:null AND
failure:null, never confirmed or a channel receipt. Required wording:
"Workflow accepted; channel delivery not confirmed".
Reject "confirmed", any nonnull receipt/remote link and unexpected fields.
Pre-send blocked/metadata failure with null marker differs from possible-send
uncertain with timestamp. Marker presence is not receipt or permission proof.
Failure EXACTLY code,nativeCode:"",httpStatus,retryAfterSeconds,retryable:false.
No Jira stage/missingFields; no raw native error echo. Explain rate delay as data,
not a timer, and uncertainty as possibly sent with no blind resend. No View Teams
message link, read receipt, channel-delivery verification or remote-link inference.
