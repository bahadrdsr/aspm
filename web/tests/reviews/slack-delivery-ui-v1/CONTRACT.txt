Exact HTTP contract
-------------------
Every protected request follows the authenticated application session and
uses X-ASPM-Workspace-ID. All browser writes use the matching loopback Origin
in this explicitly synthetic test boundary and JSON objects. This fixture
does not claim to qualify production HTTPS/cookie/CSRF middleware.
Session metadata roles and current serverRoles are independent maps. A cached
admin/analyst session never forces a successful server write after revocation.

GET  /api/v1/integrations/connections
POST /api/v1/integrations/connections
GET  /api/v1/integrations/connections/{id}
PATCH /api/v1/integrations/connections/{id}

POST input contains exactly:
  {profile:"slack-workspace-bot",name,channel,token,enabled:boolean}
Admin only. Name: Go nonblank/NUL-free text, at most 256 UTF-8 bytes.
Channel: ^[CG][A-Z0-9]{2,127}$, not a #name, search term or webhook URL.
Token: opaque nonempty text, at most 16384 UTF-8 bytes, no leading/trailing
Go whitespace or Unicode control characters. Input JSON is bounded to 32 KiB.
Enabled is an explicit boolean choice. No public operator-encryption-key
input, endpoint, header, requester, approval, profile expansion or OAuth flow.

PATCH accepts only intentional name/channel/token/enabled fields. Omission
preserves prior data. A token field starts blank on every edit; blank is not
a replacement, and unchanged tokens are not resubmitted. Only explicit new,
nonempty token input may replace it. Profile/identity/workspace are immutable.
Revision is returned server metadata, not a submitted body/header/precondition.
Meaningful changes advance it. A form draft is not an acknowledged update.

DTO contains exactly:
  id,workspaceId,profile,name,channel,enabled,credentialConfigured,
  revision,createdAt,updatedAt
POST returns 201 {apiVersion,connection}; GET/PATCH detail returns 200.
List returns {apiVersion,items,total,nextCursor}. Optional dataOrigin is
supported; this packet explicitly labels its responses synthetic.
No token, key, ciphertext, headers or endpoint may appear in metadata/errors.
Credential presence is not a connected/healthy/live-verified claim.
Missing operator encryption configuration yields 503/unavailable, never a
mock successful verification. 403 remains an authoritative server denial.
Nonsecret draft fields survive these errors with actionable guidance and
without a secret echo. Token drafts are cleared on close/success/scope/session.

POST /api/v1/findings/{id}/deliveries
  {connectionId,idempotencyKey}
GET /api/v1/findings/{id}/deliveries
GET /api/v1/integrations/deliveries/{id}

Admin/analyst may enqueue; members may read their workspace metadata/history.
A selected connection must belong to that workspace and be enabled.
Disabled enqueue is 409/conflict. Foreign/missing resources are 404.
The idempotency key is nonblank/NUL-free and at most 256 UTF-8 bytes.
Enqueue JSON is bounded to 16 KiB. No actor, payload, title/body/deepLink,
endpoint, headers, evidence or approval is submitted by the browser.
New intent: 202 queued. Same immutable binding/key replay: 200 same job,
including its current durable outcome. Changed binding: 409, not a rewrite.

Delivery DTO contains exactly:
  id,workspaceId,findingId,connectionId,connectionRevision,profile,channel,
  requestedBy,state,payload:{title,body,deepLink},createdAt,
  dispatchStartedAt:null|timestamp,completedAt:null|timestamp,
  receipt:null|{remoteId,remoteUrl},
  failure:null|{code,nativeCode,httpStatus,retryAfterSeconds,retryable:false}

Important source corrections:
  1. The actual JSON tag is receipt.remoteUrl, not remoteURL.
  2. The present Slack adapter returns channel:timestamp as remoteId and an
     empty remoteUrl. Do not construct or pretend to have a supplied Slack
     permalink. A supplied nonempty URL is a DTO value, not an invitation to
     call Slack for a permalink. The tests do not click a remote link.
  3. Native failure code rate_limited uses an underscore; delivery state
     rate-limited uses a hyphen. failed/invalid_auth can have HTTP status 200.
     Blocked preflight and lost-owner uncertainty may have HTTP status 0.
  4. The schema/shared worker admit accepted. The fixture type admits it,
     but the seven Slack outcome samples do not fabricate an accepted Slack
     response to claim a native operation that this adapter never performs.

Server snapshot at enqueue:
  title = canonical finding title
  body = "Severity: " + severity + "\nAsset: " + assetName
  deepLink = trusted process PublicOrigin + "/#/work?finding=" + encoded ID
The preview may show the current application's finding link because no
PublicOrigin discovery route exists. After acknowledgement it must use the
immutable DTO's exact link, including the synthetic server origin, rather than
rebuild it from window.location, current asset metadata or report contents.
Source code, raw evidence, original notes and remediation prose are excluded.

IDs use 32 lowercase hexadecimal characters. Lists sort by ID, with native
default limit 100, allowed 1..500, optional valid-ID cursor, total for the
whole collection and nextCursor equal to the last returned ID only when
another page exists. No invented offset/page/role/enabled filtering API.
The fixture rejects duplicate or unrelated query fields as an explicit UI
route allowlist even where the backend ignores unused parameters.
Timestamps retain RFC3339 UTC identity, including PostgreSQL microseconds.
Display may be localized; semantic time datetime values retain the source.

State, intent and lifetime semantics
-----------------------------------
Queued means durable intent, not sent/accepted/confirmed. Dispatching is not
confirmation either. Only a confirmed native receipt is confirmed. An
independent native worker changes the durable status; the browser never
dispatches work or calls a fabricated send/retry API.
Blocked, failed, rate-limited and uncertain retain failure details. Retry-After
7 seconds is data only. It must not start an enqueue/send timer.
Terminal uncertainty says the outcome cannot be confirmed or may already
have occurred, and offers no retry/resend/send-again control. Read-only
"Refresh delivery" remains useful. No exactly-once or undo-remote-write claim.

Network loss after enqueue is different from a durable uncertain result.
The fixture persists the synthetic intent before dropping/holding its ACK.
Before a user explicitly confirms the same unresolved intent again, either:
  A. retain its exact connectionId + idempotencyKey and accept a 200 replay
     with the same immutable ID and full durable result; or
  B. prevent a new attempt until an authorized manual history read reconciles
     the original job. Never silently turn lost acknowledgement into a fresh
     idempotency key or automatic duplicate enqueue.
Closing a modal or canceling fetch is not represented as a server rollback.

Workspace changes, logout and 401 remove protected connection/form/preview/
delivery/history state, abort old in-flight reads/writes, and discard late
responses or committed ACKs. Switching via the real Workspace control is
explicit in multi-phase tests: hash navigation does not reset a valid scope.
After a detail 403/404, old detail metadata remains withheld through subsequent
503 retries until a new authorized read succeeds. An independently authorized
parent table is not required to disappear merely because its detail is denied.

A notification never resolves a finding, changes owner/workflow/disposition,
relabels scanner inference or claims independent verification. Its status
must not replace original evidence, observation timestamps, analyst context
or Work filter/selection/focus/scroll.

Semantic UI surface
-------------------
Reuse existing shared shadcn/Animate controls, FormDialog, finding dialog,
scoped resource/action and session patterns where useful. No new third-party
form/chart/widget dependency. No implementation class names, test IDs,
component internals, native-dialog-only checks, forced focus target or
particular DOM repair technique is prescribed by this packet.

Small discoverable controls with accessible names:
  Connections region and table; Add/Create/New connection; Refresh connections.
  Labelled connection form: Name, Channel ID, bot token, explicit Enabled.
  Edit connection; contextual Save; revision from the returned server metadata.
  Notify/Send to Slack inside the finding dialog, not a global bulk toolbar.
  Small named notification preview/form, selected Connection and confirmation.
  Delivery history and Deliveries table, optionally opened by a disclosure.
  Open/View delivery; named Selected delivery region and Delivery status.
  Refresh delivery and Refresh delivery history; contextual Retry for reads.
Equivalent aliases listed in the spec are intentional, not implementation
requirements. Native or accessible custom connection/enabled selectors are
allowed. Disabled selector entries may be absent or truthfully disabled.
Paging may append or replace the returned page while following nextCursor.

The dialog must be keyboard reachable, keep focus inside while active, allow
Escape/cancel and restore sensible context. At 390x844, long valid names,
channels and payload context must fit without full-document horizontal
overflow, with reachable dialog scrolling. Reduced motion affects real CSS
and Web Animations, not only a preference attribute. Work query, selection,
trigger focus and actual scrolled position survive cancel/confirmation.
